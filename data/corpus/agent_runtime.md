# 知识 Agent 执行、证据与 Trace

## 执行循环与限制

`KnowledgeLoop` 以 Python 显式控制一次运行：有历史时先把追问解析为独立检索问题，再执行 Vector + BM25 + RRF 初始检索，建立本轮证据账本，随后根据模型输出决定回答或调用只读工具。对照模式复用循环但关闭工具。

正式知识工具只有 `search_knowledge` 与 `read_document`。模型提交 structured tool call；`KnowledgeToolExecutor` 在 Python 中校验参数、限制访问范围并执行只读操作。工具失败会被记录为执行结果交给循环处理，但不能据此承诺所有错误都可恢复。

预算由代码控制：最多 8 次模型调用、6 次工具尝试、120 秒总时限、20000 字符的证据预算；工具阶段在最后至少 30 秒前停止，以便尝试收尾。若有历史问题补全，也占用模型调用和总时限。

## 证据、引用和 Trace

`EvidenceStore` 为本轮证据分配稳定编号，维护来源、读取范围、已交付文本和覆盖状态，并限制证据字符预算。回答校验会检查引用编号是否来自本轮证据、正文内编号是否与列表一致；编号合法不等于证据在语义上支持结论。

Trace 持久化 run、步骤、工具调用、结果和运行元数据，适合检查执行路径。模型原生 reasoning 字段只保留在循环内存中，不作为完整私有思维链写入 Trace；Trace 不等于模型全部内部推理过程。旧 Trace 返回字段保留读取兼容。

API 的 SSE 在请求期间迭代 Agent 事件。连接结束会执行取消收尾；它不是可靠后台队列，也不提供断线续跑或任务自动恢复。模型、数据库或检索失败可能使本次 run 失败，应依据实际 Trace 与错误状态判断，而不是假设已自动降级成功。
