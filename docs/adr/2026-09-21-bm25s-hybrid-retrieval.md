# ADR：词法检索采用 bm25s

## 决策时间线

### 2026-09-21：实验未达到提升门槛

初始问题是词法分支只按命中 token 数排序，没有 BM25 的词频、逆文档频率和长度归一化。决定使用 Python `bm25s` 做对比实验；PostgreSQL 继续作为文档、切片、元数据和向量的事实来源，稠密分支继续由 pgvector 提供。RRF 融合排名，不把不同检索器的原始分数直接按固定权重相加；暂不引入 PostgreSQL FTS 或额外数据库扩展。

实验使用当时冻结的 22 个问题、481 个切片和 Ollama BGE-M3。历史结果如下：

| 模式 | Recall@3 | Recall@5 | MRR@5 |
| --- | ---: | ---: | ---: |
| vector | 0.909 | 1.000 | 0.884 |
| old keyword | 1.000 | 1.000 | 0.932 |
| BM25 | 0.955 | 0.955 | 0.932 |
| old/default hybrid | 1.000 | 1.000 | 0.977 |
| BM25 hybrid | 1.000 | 1.000 | 0.977 |

预先设定的门槛要求 Recall@5 不退化，并且 MRR@5 或 Recall@3 至少一项提升。BM25 hybrid 与旧混合路径指标持平，因此未满足提升门槛；BM25-only 还漏掉一个并发写入问题的目标来源。2026-09-21 当时的结论是旧关键词路径仍作默认，BM25 留作可重复对照。

### 2026-09-23：为维护一致性统一检索路径

产品随后改为使用 Vector + BM25 + RRF 作为统一检索路径，以减少维护与 Trace 行为分叉。该变更是简化决策，不是质量提升的实测结论；2026-09-21 的实验结果和未通过门槛的结论不变。Agent 与关闭工具的对照模式共享初始检索及证据处理循环。

## 后果与边界

- BM25 索引在进程内按语料指纹感知变动并按需重建；PostgreSQL 仍是原始文档、切片和向量的权威存储。
- 历史评测数字仅反映上述旧语料、旧问题集与运行环境，不代表当前公开语料质量、当前检索效果或新切片验收。当前候选池和初始交付配置以 `CONTEXT.md` 与实现为准。
- 是否提升检索质量需用匹配当前语料与问题集的评测验证，不能从本 ADR 的维护取舍推断。
